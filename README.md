# team3 — 図形の特徴点スナップ

画像認識の授業の班課題です。画像の図形から特徴点（上下左右・頂点・くぼみ）を見つけて、
**図形を動かすと特徴点どうしがピタッと揃う「スナップ機能」** を持つ、プレゼン資料づくり・描画ツールのようなアプリを作ります。

PowerPoint は図形の外枠（四角い枠）で揃えますが、このアプリは**画像から見つけた特徴点**で揃えます。
たとえば星なら、とがった先端そのものをスライドの端や他の図形の角に合わせられます。

## 進め方

| 段階 | 内容 | 時期 |
| --- | --- | --- |

| 2. 発展 | **deep learning** と組み合わせて、写真やイラストなど複雑な画像にも対応する | 最終発表（12/28）まで |

## アプリ

### できること

**図形**

- 16:9 のスライドに図形を置いて、ドラッグで動かす
- 他の図形の特徴点や、スライドの端・中央に近づくと、ガイド線が出て吸い付く
- クリックで選択、四隅のつまみで拡大縮小、Delete キーで削除
- 上のバーのボタンから図形を追加
- 特徴点の印の表示 ON/OFF（隠してもスナップは効く）
- ウィンドウの大きさを変えても、図形はスライドの中の同じ位置に残る

**テキスト**

- 「T」ボタンでスライドの真ん中にテキストを置き、そのまま文字を打てる
- Enter で確定、Shift + Enter で改行、Esc で取り消し。ダブルクリックでもう一度編集できる
- テキストを選ぶと、上のバーでフォント・大きさ・色・太字を変えられる
- テキストは外枠の 9 点（左端・中央・右端 × 上端・真ん中・下端）でスナップする

**画像**

- 画像ボタン（額縁の絵）でファイルを選ぶか、画像ファイルをスライドにドラッグ＆ドロップして追加する
- 画像の種類によって、スナップのしかたが自動で変わる（追加したときに画面の下にお知らせが出る）

| 画像の種類 | 見分け方 | スナップ |
| --- | --- | --- |
| 図形らしい画像 | 周りがほぼ一色で、使われている色が少ない | API（画像処理）で見つけた特徴点 |
| 写真など | 上以外 | 外枠の 9 点（テキストと同じ） |

- 図形らしく見えても特徴点が見つからなかったとき、API が動いていないときは、外枠でスナップする

**保存**

- 「PNG で保存」で、スライドを 1920×1080 の画像（`slide.png`）として保存する
- 特徴点の印・選択の枠・ガイド線は写らない。スライドからはみ出した部分は切り取られる

> 画面のファイルを更新したのに表示が変わらないときは、ブラウザで `Ctrl + Shift + R` を押して読み込み直してください。

### 起動のしかた

画面と API を1つのコマンドで起動します（仮想環境を有効にしてから、team3 フォルダで実行）。

```bash
uvicorn app.server:app --reload
```

- アプリ：http://localhost:8000/
- API を単体で試す画面：http://localhost:8000/docs
- 止めるとき：Ctrl + C

図形を置くと、画面がその画像を API に送り、画像処理で見つけた特徴点を受け取って表示します。
API の詳しい使い方は [docs/api.md](docs/api.md) を見てください。

## コードのルール

### 検出関数の形をそろえる

`main.py` や API から全員の結果をまとめて呼ぶため、各ファイルには同じ形の関数 `detect` を作ります。

```python
def detect(contour):
    """contour: features/preprocess.py の find_shapes() が返す輪郭1つ"""
    return {"ラベル": [(x1, y1), (x2, y2), ...]}
```

- 座標は `int` の `(x, y)` にする（左上が原点、y は下向きが正）
- ラベル名は「特徴点と担当」の表のとおり。新しく追加するときは、`main.py` の `STYLES` と `app/static/app.js` の `STYLES` に色も追加する

### 点の選び方（班で決めたこと）

スナップで吸い付く先として役に立つかどうかで決めています。

- 同じ高さ（または同じ横位置）で**離れた場所にある点は全部返す**（例：星の下の2つの先端）
- 四角形の上辺のような**平らな辺は、真ん中の1点**を返す
- 別々の検出で**同じ場所に重なった点は1つにまとめる**（例：星のてっぺんの T と V）
- 円や雲の曲線の途中には頂点を出さない（とがった角だけを頂点にする）

### 画面と API の間のデータの形（JSON）

画面は図形の画像を API に送り、API は次の形で特徴点を返します。

```json
{
  "width": 400,
  "height": 400,
  "points": {
    "top": [[200, 50]],
    "bottom": [[111, 321], [288, 321]],
    "left": [[57, 153]],
    "right": [[342, 153]],
    "vertex": [[200, 50], [342, 153]],
    "concavity": [[236, 151]]
  }
}
```

- `width`, `height` は元の画像の大きさ。座標は元の画像の上での位置
- 1枚の画像に図形は1つの前提（中間発表まで）

### 共通部分

- `features/preprocess.py` と `main.py` は全員が使います。変更するときはチームに一言相談してください
- テスト画像は `images/` に入れて共有します。どんな図形で試したかがみんなに分かるようにするためです

## Git のルール

1. **`main` に直接 push しない**
2. 作業前に最新の `main` を取り込む
   ```bash
   git switch main
   git pull
   ```
3. 自分用のブランチを作って作業する（名前は `feature/内容`・`fix/内容`・`docs/内容`）
   ```bash
   git switch -c feature/extremes
   ```
4. こまめにコミットして push する
   ```bash
   git add .
   git commit -m "星形の上下左右に対応"
   git push -u origin feature/extremes
   ```
5. GitHub でプルリクエストを作り、**他のメンバー1人に見てもらってから** `main` にマージする
